{% call macros::icon("database") %} Application Data

Backs up this control plane's own persistent data: the MariaDB database (always), a redacted snapshot of this process's own configuration, and -- opt-in, always encrypted -- the ENCRYPTION_KEY used for Panopticon/macro secrets. A database dump alone is not enough for a real restore; this is the whole self-contained archive.

{% call macros::icon("warning") %} Backups written here live on this same host/disk as the application. That does not protect you against losing the whole host or disk. Copy backups to a separate disk, NFS share, or off-host location on a regular basis.

{% call macros::icon("settings") %} Control-Plane Configuration

Schedule, retention, and destination for backups -- also this section's own settings panel (GitHub issue #9's "Control-Plane Configuration" is functionally this settings form plus the "Configuration" component above; there's nothing else runtime-configurable to separately back up beyond what's already captured there).

Scheduled backups are never encrypted (there's nobody present to supply a passphrase) -- back up Database + Configuration (+ Audit logs, per the setting below) only. Use manual backups for anything encrypted.

Must be a path inside this container -- mount it to a dedicated volume separate from the database's own (see docker-compose.yml's abyssal_backups volume).

Controls the "Audit logs" checkbox's default on the form above, and whether scheduled backups include the audit_log table. Unchecking this excludes only that table's rows (via mariadb-dump --ignore-table) -- the rest of the database is unaffected either way.
