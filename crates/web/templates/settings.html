{% call macros::icon("danger") %} Host network isolation

Gates Inquest's full host isolation -- can sever a host's own manageability with no remote fix.

Learn more

Blocks all network traffic except the control plane's own connection. Unlike every other destructive operation this platform dispatches, a wrong edge case here (NAT, a DNS-based control-plane address, a multi-homed host) can sever the agent's own connection back to the control plane with no remote way to undo it -- recovery would need physical or console access to the host. Off by default; this is a second, deliberate layer on top of (not instead of) the type-to-confirm the operation still requires.

{% if host_isolation_enabled %}Enabled{% else %}Disabled{% endif %}

Monitoring & Alerts

{% call macros::icon("audit") %} Thanatos background monitoring

Unattended sweep that scans every host's security logs and can raise alerts on its own.

Learn more

A fixed-interval sweep that scans every connected host's security logs, persists what it finds, and can raise correlation alerts on its own -- nobody has to click anything. Off by default: this reads and stores security-log content across your whole fleet automatically once enabled. Manual, admin-triggered scans from the Thanatos page work regardless of this setting; it only controls the unattended sweep.

{% if thanatos_monitoring_enabled %}Enabled{% else %}Disabled{% endif %}
{% call macros::icon("audit") %} Thanatos alert recipients

Who gets notified when Thanatos raises a correlation alert.

Learn more

Comma-separated email addresses, sent through whatever notification provider is configured (SMTP today, set via environment variables). An alert is still recorded and shown on the Thanatos page even with no recipients set -- this only controls whether it's also actively pushed out.
